Verbatim

语音输入，逐字为准。按一下开始说，再按一下，文字直接插进光标处。
默认不改写——重复、口头语、自我修正都留着。改多少，由你决定。

为什么是「逐字」

大多数语音输入会在你说完之后替你润色：删口头语、合并重复、把话改写成书面语。 这个动作很危险——改写意味着有人替你做判断，而你不知道它改掉了什么。 Verbatim 的默认行为是原样插入，所有调整都必须是你能看见、能关掉的具体规则。

三个核心机制

01 · Alias corroboration

别名互证：没有第二意见就不改

个人词库可以登记「常被听错成的写法」。但别名本身可能就是真词—— 把 skill 登记成 SKU 的别名，用户真说「不是 SKU，是 skill」时， 无脑替换会把话说反。

所以规则是：只有第二个独立引擎在同一位置听到正确写法时才改写。没有第二引擎，一个别名都不改。 第二引擎通过本地 whisper 命令行接入。这不是缺功能，是刻意设计。

02 · Context budget

上下文预算：这次说话带哪些词

引擎能接受的上下文条数有限，词库可能有几百条，不能全塞进去。排序不是先来先到：

因子权重
置顶+1000
当前应用命中+150
被纠正次数+20 / 次，上限 +100
最近使用+80 按天递减到 0
纠错被撤销（误判）−100 / 次，上限 −400
03 · Insert shaping

插入整形：按宿主改标点

宿主行为
聊天去掉句末一个句号；省略号、版本号小数点不动
文档 / 代码原样
终端去掉末尾换行，不替你按回车

英文之间自动补空格，但中文后面接英文不补。

构建与安装

只需要 Command Line Tools，不需要完整 Xcode。

# 拉源码
git clone https://github.com/hakalsteven-dot/verbatim-voice.git
cd verbatim-voice

# 跑核心逻辑测试（60 项断言）
./scripts/test.sh

# 构建 / 构建并安装
./scripts/build-app.sh
./scripts/build-app.sh --install

首次运行需要在「系统设置 → 隐私与安全性」里授予三项权限：

权限用途
麦克风录音
语音识别把话转成文字
辅助功能把文字插进其他应用的输入框
⚠︎
应用未经 Apple 公证，首次打开可能被 Gatekeeper 拦下。双击一次后到「隐私与安全性」点「仍要打开」，或运行 xattr -dr com.apple.quarantine /Applications/Verbatim.app。

实现说明

逻辑与界面分离：VerbatimCore 不依赖 AppKit，所以核心规则能在命令行里跑测试。 插入用「写剪贴板 + 模拟 ⌘V」而不是逐字 AX 写入，兼容性更好，也不会打断输入法状态。 

├── Sources/VerbatimCore/    纯逻辑，无 UI 依赖
│   ├── TextJoinPolicy.swift
│   ├── ContextBudgeter.swift
│   ├── MisrecognitionNormalizer.swift
│   ├── PersonalLexicon.swift
│   └── DictationPipeline.swift
├── Sources/Verbatim/        应用层：录音 / 识别 / 插入 / 热键
├── Tests/                   可移植断言 + XCTest 两套
└── scripts/                 build-app.sh / test.sh

与原项目的关系

本项目参考了 Towow-ai/totype 的产品判断（逐字优先、改多少由用户决定、别名需互证），代码为本项目重新编写： 逻辑层重写为可单测的纯函数并补了 60 项断言，插入规则与预算取值重新设计，界面用 SwiftUI 全新实现， 第二引擎只提供本地 whisper CLI 一种接入。
